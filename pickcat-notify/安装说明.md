# pickcat 通知 · 安装说明（V2.6.9）

一个浏览器扩展。**关掉 Pickcat 网页后，它会在后台继续帮你查未读消息，有新消息就一条条弹系统通知，并写清是谁、做了什么、哪条内容；点通知直达那一楼。**弹窗界面按 Pickcat 官网的配色和排版重做过一遍，还能按 @我 / 回复 / 赞 / 系统 直接筛最近几条。

支持 Chrome、Edge 等 Chromium 内核浏览器。作者：[羽Yu](https://pickcat.dao3.fun/profile/01a101ad-91a6-7def-9134-a1b7ebe27c2b)。

---

## 一、安装

1. 打开扩展管理页：
   - Chrome：地址栏输入 `chrome://extensions/`
   - Edge：地址栏输入 `edge://extensions/`
2. 打开 **开发者模式**（Chrome 在右上角，Edge 在左下角）。
3. 点 **加载已解压的扩展程序**，选中 `pickcat-notify` 这个**文件夹**（不是里面的文件）。
4. 装好后会自动弹出一个**引导页窗口**，同时收到**一次**测试通知。之后就只在真的有新消息时提醒。

> 已经装过旧版的：在扩展卡片上点**刷新**（重新加载），新界面就生效了。

---

## 二、先登录

插件读的是你自己账号的未读消息：

1. 在浏览器里打开 <https://pickcat.dao3.fun/> 并登录；
2. 在引导页或弹窗里点 **立即检查**；
3. 能读到数字 = 通了；读不到会直接写明原因（未登录 / 网络不通 / 限流）。

## 三、界面（三块）

**① 工具栏弹窗** —— 打开就能看懂：
未读数、状态标签（已连接 / 未登录 / 已关闭）、上次检查与间隔、**最新动态**（条数同「通知里最多列几条」，1～5 条；每条含发送者头像、昵称、分类标签、所属帖子标题、楼号和时间；有帖子标识的动态整行可点直达）、**分类筛选**（全部 / @我 / 回复 / 赞 / 系统，后面跟着这一类在最近几条里的条数，点一下只看这类；没有这类时给一个「去消息中心看全部」的入口，直达站点对应 tab）、多久查一次、立即检查、全部已读、更多设置；最底下一行是**「检查更新」**（有新版本时直接变成「有新版 vX · 去下载」）。（测试通知不在弹窗里，挪到了设置页底部的小链接）

**② 引导页**（装完自动弹出一次）
01 先登录 → 02 点一次立即检查 → 03 之后网页可以关掉；下方是实时状态和能力边界。

**③ 设置页**（弹窗里点「更多设置」）
检查间隔、检查方式、提醒开关、免打扰、**版本与更新**、**后台体检**、**关页验证**。

| 设置项 | 说明 |
| --- | --- |
| 多久查一次 | 六档横排：**30 秒 / 1 / 3 / 5 / 10 分钟 / 半小时**。30 秒靠内部计时器真跑 30 秒，浏览器闹钟最细 1 分钟，只当兜底 |
| 检查方式 | 默认 **智能**：你开着 Pickcat 页面就直接读它；没开就直连接口（一个页面都不开）；直连还读不到才建一个最小化的后台页兜底；兜底也失败就报错说明原因。点「其他方式…」弹出小面板，三种方式可**自己勾、按勾选先后排顺序**（勾几个就按 1、2、3 依次试，前一步不成才走下一步）；**三个全勾就等于智能** |
| 桌面通知 | 总开关（滑块）。关掉后下面这些设置会整块变灰、点不动；弹通知、提示音、角标一律停，后台检查照常跑（站内未读数字仍然会更新） |
| 通知里最多列几条 | 1 / 2 / 3 / 4 / 5 条。多了只列最近的，其余写成「还有 N 条」 |
| 图标上显示未读数字 | 开关，默认关；未读靠图标右下角那块变红提示 |
| 通知带提示音 | 开关；关掉就静默弹窗 |
| 哪些消息要弹通知 | 四类打勾开关，名字和站点一致：**提到我的（@）** / **回复我的** / **收到的赞** / **系统通知**（关注、管理通知、等级认证、申诉结果、关注帖动态）。勾掉哪类，那类就不弹 |
| 免打扰时段 | 开关 + 起止时间（例如 22:30–07:00）；时段内不弹通知，未读照常统计、不补弹 |
| 版本与更新 | 显示当前版本，点「检查更新」直连 GitHub 查最新版；有新版本时按钮变成「去下载新版」，没有则写「已是最新版本」。同一结果缓存 6 小时，不会每开一次设置页就联网 |

> 三个页面都**跟随系统的深浅色**：Windows 用深色主题，界面自动变深色，不用手动切。下拉框全部换成自绘的分段控件，不出现浏览器原生控件。
>
> **配色和排版跟 Pickcat 官网一套**：品牌红 `#fa322d` 只用在关键处（开关打开、选中的分段、未读数、主按钮、分区小竖条），页面底 `#f6f6f7`、卡片白底 + 1px 细边、卡片圆角 12px、控件圆角 6px，正文灰阶取官网的 `#1f1f1f / #444 / #6e6e6e / #8e8e8e`，字体栈也换成官网那套 system-ui 优先。没有渐变、没有大阴影，尽量跟站内页面看起来是同一个东西。

## 四、通知长什么样

**有新消息时，一条消息弹一条通知**——标题就是谁做了什么，正文是所属帖子和楼号；点这条通知直达对应帖子并定位到那条评论：

```
starry 赞了你的帖子
《GPT，大肥鱼全天Bot？！》 · 第 12 楼
```

**超过「通知里最多列几条」时，多出来的合并成一条汇总**（不会一次刷满屏）：

```
还有 3 条新消息
前面几条已经单独提醒过，点这里看全部
```

去重规则：**同一条消息只提醒一次**。插件按站点给的消息 id 记账，已经弹过、或者第一次装上时就已经存在的旧未读，都不会再弹；免打扰时段里来的消息也不补弹。

支持的动静都会翻译成中文：赞了你、关注了你、回复了你的评论、回复了你的帖子、在帖子里 @了你、你关注的帖子有新动态、等级认证出结果了、下架申诉有结果了。

## 五、关掉网页 / 关掉浏览器，到底能不能收到

| 情况 | 能不能收到 |
| --- | --- |
| 关掉 Pickcat 标签页 | **能**。定时检查跑在浏览器后台，不依赖网页 |
| 关掉浏览器窗口、但进程还在后台运行 | **能**。前提是 Chrome 设置里打开「关闭浏览器后继续运行后台应用」 |
| 完全退出浏览器 / 关机 | **不能**。浏览器进程不在了，插件随之停止 |

设置页底部有 **「关掉所有 Pickcat 页面后测试」** 按钮：会真的关掉所有 Pickcat 页面，然后立刻检查一次并写出结果。

## 六、它是怎么拿到消息的

- 未读数：`GET /api/v1/notification-summary` → `unreadCount`
- 消息列表：`GET /api/v1/notifications?limit=5` → `items[]`（类型、发送者昵称与头像、所属帖子标题、楼号、已读状态）
- 全部已读：`PATCH /api/v1/notifications` + `{ "read": true }`——**只有你手动点弹窗里的「全部已读」才会发**，平时绝不写数据。
- 登录状态走 Cookie（和网页本身一样），插件**不保存密码**。
- 检查由浏览器定时任务（`chrome.alarms`）+ 30 秒计时器驱动，不依赖任何网页是否打开。
- **按消息 id 去重**：第一次装上、或者隔了很久没开，列表里的旧未读只记账不弹；之后只弹「以前没见过、还没读、类型开着」的那几条，同一条消息只弹一次。
- 通知文案固定是「**谁 + 做了什么 + 什么内容**」，例如「编程猫子涵awa 赞了你的帖子 / 内容：……」；类型名和站点自己的四个分类对齐（提到我的、回复我的、收到的赞、系统通知）。
- **检查更新**：直接问 GitHub 的 Releases 接口（`api.github.com/repos/Yu-pickcat/pickcat-notify/releases`），拿最新一条的 tag 比版本号；这个接口不通时，同时拉 `raw.githubusercontent.com` 和三个 jsDelivr 镜像里的 `manifest.json`，**取其中版本号最大的那个**（各节点缓存进度不一样，不能第一个成功就算数）。这些源都带跨源放开头，不需要多申请任何域名权限。
- 升级安装时会弹**一次**「已更新到这个版本」，带「看看更新内容 / 以后再说」两个按钮，同一个版本只弹一次。

## 七、和 PICKCAT Plus / PickScribe 一起装

**能同时装，互不顶掉。** 实测三者在同一个 Chrome 里各装各的：

| 会不会打架 | 实际情况 |
| --- | --- |
| 数据 | `chrome.storage.local` 按扩展隔离，Plus 的 `pickcat_update_check`、PickScribe 的 `pco_notify`、本扩展的 `settings/state/notifySeen` 互不可见 |
| 定时器 | 闹钟名不同（本扩展 `pickcat-tick`、PickScribe `pco-notify-poll`），各跑各的 |
| 通知 | id 前缀不同（本扩展 `pickcat-`、PickScribe `pco-`），清理只清自己的，不会互相清掉 |
| 页面 | Plus / PickScribe 会在 Pickcat 页面里画工具栏和面板；**本扩展不往页面里画任何东西**（只有首次引导页和设置页），不会遮挡它们的界面 |
| 重复开标签 | 消息中心、更新页这类不带锚点的地址，**已经开着就直接切过去**，不再开第二个；不会因为两个扩展都提醒而开出一排重复的消息中心标签。带 `#post-<楼号>` 的帖子链接每层楼是不同目标，照旧新开 |
| 重复提醒 | 唯一会重复的地方：**两个扩展都开了桌面提醒时会各弹一条**。建议只留一个开提醒，另一个关掉（本扩展在弹窗顶部一键关） |

装多个提醒类扩展时，Windows 通知中心里会同时出现几组通知，看到同一条消息被提醒两次就是这个原因，不是 bug。

## 八、权限说明（装的时候 Chrome 会列出这些）

| 权限 | Chrome 显示的名字 | 实际用途 | 边界 |
| --- | --- | --- | --- |
| `alarms` | 与你无关的提醒/定时器 | 每分钟醒一次去查未读数 | 只有插件自己的闹钟，不碰系统计划任务 |
| `notifications` | 显示通知 | 有新消息时弹系统通知 | 只弹自己创建的通知 |
| `storage` | 存储数据 | 存你的设置、上次读数、最近三条动态 | 存在浏览器本地，不上传 |
| `host_permissions` | 读取和更改您在 pickcat.dao3.fun 上的数据 | 调 `/api/v1/notification-summary` 等接口；直连读不到时才建一个最小化兜底页 | **只限 pickcat.dao3.fun 这一个域名**，其他网站一律无权 |

> 检查更新只请求 `api.github.com`、`raw.githubusercontent.com` 和 `jsDelivr`，这些源都返回 `Access-Control-Allow-Origin: *`，所以**没有为了查更新多申请任何域名权限**，权限从 2.4.7 起就没再变过。

**关于「读取您的浏览记录」**：这个提示原本来自 `tabs` 权限。2.1 版已经把它去掉了——实测在只有站点级权限的情况下，插件依然能找出你开着的 Pickcat 页面、也能管理兜底页，而其他网页的地址、标题一律读不到（实测返回 `url: null`）。

插件**不读**：你的密码、其他网站的浏览记录、剪贴板、文件系统；**不写**：不发帖、不评论、不点赞、不改任何内容——所有请求都是 `GET`，**唯一例外是你手动点「全部已读」时的一条 `PATCH`**。

## 九、已知限制（实测出来的）

1. **窗口不能放到屏幕外。** Chrome/Edge 会报 `Bounds must be at least 50% within visible screen space`，所以不能靠「屏幕外小窗口」藏起来。
2. **默认的读取顺序**：先找你已开着的 Pickcat 页面 → 没有再直连接口 → 直连也读不到才建兜底后台页。只要你自己开着页面，它就只读那个页面，**不会在标签栏里另开一个标签**。想改顺序就用「其他方式…」自己勾，勾几个就按勾的先后依次试。
3. **兜底后台页是最小化的独立小窗**：不进标签栏、不抢焦点，页面加载完会连压三次最小化。它只有在你「一个 Pickcat 页面都没开、直连又读不到」时才会被建一次，之后一直复用。
4. **兜底页会被关闭。** 你手动关掉它，下次真的读不到时才会再建一个。
5. **间隔最快 30 秒。** 30 秒这档用内部计时器（`setTimeout` 链）真跑；浏览器的定时闹钟最细 1 分钟，只当「进程被挂起时唤醒」的兜底，所以体检里的「定时任务」一行会写成「每 30 秒（计时器执行，闹钟 1 分钟兜底）」。
6. **系统睡眠期间不检查**，唤醒后恢复。
7. **桌面通知只有一个图标位**：Chrome 系统通知不能在文字旁边再塞一张独立头像小图。每条新消息的通知图标直接用发送者头像；对方没头像、或是「还有 N 条」汇总时，回退扩展自带图标。另外站点接口不返回回复正文，通知里只能给出所属帖子标题和楼号；点开用站点自带的 `#post-<楼号>` 锚点（和消息中心里回复通知的链接一模一样），页面加载后会自己滚动定位到那一楼，实测有效。
8. **头像走后台中转**：站点头像接口带跨源限制（`cross-origin-resource-policy: same-origin`），扩展弹窗页面不能直接 `<img>` 拉取；扩展由后台把头像抓成 data URL 再显示到弹窗和通知图标里，抓不到时退回昵称首字母圆形占位。
9. **检查更新要能连上 GitHub**：主路径是 `api.github.com` 的 Releases 接口；不通时并行拉 `raw.githubusercontent.com` 和三个 jsDelivr 镜像，取版本号最大的那个。实测国内网络里 jsDelivr 有时整段打不开、`raw.githubusercontent.com` 反而正常，所以 raw 排在第一位；各镜像节点缓存进度不一，只认「最大版本」就不会被旧节点带偏。GitHub 未登录接口每小时限 60 次，手动点几下完全够。
10. **只在扩展页里查更新，不自动后台轮询**：解压加载的扩展本来就没有自动更新通道，所以做成了「打开设置页时用 6 小时内的缓存结果，点按钮才真去查」，不吃后台流量。

## 十、排错

| 现象 | 处理 |
| --- | --- |
| 「未登录」 | 先在浏览器里登录 pickcat；或者干脆开着 Pickcat 页面（智能模式会直接读那个页面） |
| 测试通知没动静 | Windows 设置 → 系统 → 通知 → 允许 Chrome/Edge 通知 |
| 后台体检显示「没注册」 | 弹窗顶部总开关被关掉了，打开即可 |
| 一直「网络不通」 | 检查网络 / 代理，或站点临时故障 |
| 扩展错误页出现 `No current window` | 浏览器刚启动、窗口还没就绪时后台开标签页失败；2.4.5 起会自动等一下重试一次，刷新扩展即可，不影响正常使用 |
| 检查更新点不动 / 一直「检查中…」 | 多半是 GitHub 连不上（代理、网络）；等一会儿点「重试」，或直接看仓库 Releases 页 |
| 检查更新显示的还是旧版本号 | 镜像节点有 CDN 缓存，可能还停在旧版本；已经改成「多镜像并行、取最大版本号」，等一次检查（或点「再检查一次」）就会取到最新的 |

## 十一、文件清单

```
pickcat-notify/
├─ manifest.json     扩展配置（MV3）
├─ ui.css            三个页面共用的界面样式
├─ background.js     后台：定时检查、按 id 去重逐条弹通知、点通知直达落盘链接、角标、检查更新、引导页调度
├─ content.js        在 Pickcat 页面里读未读数和消息列表
├─ popup.html/.js    工具栏弹窗
├─ welcome.html/.js  首次打开的引导页（只弹一次）
├─ options.html/.js  设置页 + 后台体检 + 关页验证
└─ icons/            16 / 24 / 32 / 48 / 64 / 96 / 128 / 192 / 256 全档图标（官网 logo 里抠出的墨黑 C + 右下角 45° 斜块：无未读与字同色，有未读变品牌红；另有一组灰化的 idle 版留给已关闭 / 免打扰）
```
